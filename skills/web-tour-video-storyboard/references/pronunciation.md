# 发音规则

## 显示文本 vs 朗读文本

- `narration`：干净原文，用于字幕和审阅。**不能出现拼音、CMU、数字读法标记。**
- `tts_text`：可选，手写朗读文本，优先级最高，不再套 lexicon。
- `lexicon`：全局替换，按匹配串长度从长到短、单次扫描、不二次替换。

## 多音字

只替换需要纠正的那个字，用大写拼音 + 声调数字：

```json
{ "match": "重要", "tts": "ZHONG4要" }
```

官方示例：

```text
这批货物打ZHE2出售后他严重SHE2本了，再也经不起ZHE1腾了。
```

优先改写措辞避开，例如“重新尝试”代替“重试”。

## 英文

CMU 音素，大写、空格分隔、方括号：

```text
He plays the [B EY1 S] guitar while catching a [B AE1 S] fish.
```

- 只支持 CMU，**不支持 IPA**：`/siː/`、`/ˈbɔːldər/` 会被当字面量读。
- 品牌名先问用户怎么读，确认后转 CMU。例：`Acme` → `[AE1 K M IY0]`（AK-mee）。
- 中英混排的近似音（如“西包德尔”）可以兜底，但和英文读音容易打架；用户要英文音标时不要用中文近似音。
- 不确定的音素不要瞎写，列出来问用户。

## 数字

不要交给 TTS。写朗读文本时转成汉字：

- `123` → `一百二十三`
- `3.0` → `三点零`
- `50%` → `百分之五十`
- `v2.1` → `二点一版本`
- 日期按口语读法

脚本会校验；残留阿拉伯数字直接报错。

## 未验证

- `ü` 的 `lv` / `nv` 写法、轻声标记：官方示例未覆盖，不要自动用。
- 非语言标签（`[laughter]` 等）：演示旁白不用。
